# yt-transcript-extractor

유튜브 영상 URL을 넣으면 **타임스탬프가 붙은 자막**을 `.md` 로 추출하는 스크립트.

URL 하나만 넣으면 **자막 추출부터 한국어 요약까지 한 번에** 끝난다.

```bash
python3 yt-transcript.py "https://www.youtube.com/watch?v=VIDEO_ID"
```

```
transcripts/<제목>.md   ← 영상 원본 언어 자막, 45초 문단, 타임스탬프 점프 링크
summaries/<제목>.json   ← 한국어 요약 (정본)
summaries/<제목>.md     ← 한국어 요약 (읽기용)
```

- 자막은 **영상 원본 언어**로 뽑는다. 번역은 요약 단계에서 한다([왜 그런지](#번역은-요약-단계에서-한다)).
- **45초 단위로 문단화**된다. 자동 자막의 2초짜리 조각을 읽을 수 있는 덩어리로 묶는다.
- 요약은 **한국어**로, 슬랙·카카오톡으로 바로 보낼 수 있는 구조로 나온다.
- 같은 URL 을 다시 돌리면 세 파일 모두 덮어쓴다.

`--no-summary` 를 주면 자막만 뽑고 멈춘다.

```markdown
[`00:01:28`](https://www.youtube.com/watch?v=VIDEO_ID&t=88s) 자막 문단 텍스트가 45초 단위로 묶여 이어진다...
```

후처리·RAG 색인용 구조화 데이터가 필요하면 `--format json` 으로 `start` / `end` / `timestamp` / `text` 세그먼트 배열을 받을 수 있다.

## 요구 사항

- Python 3.9+
- [`yt-dlp`](https://github.com/yt-dlp/yt-dlp) — `brew install yt-dlp`
- 요약 단계에만: [`claude` CLI](https://claude.com/claude-code) (로그인된 상태), 슬랙 렌더링에는 `jq` 불필요

요약은 `ANTHROPIC_API_KEY` 없이 **로컬에 설치된 `claude` CLI 를 헤드리스(`-p`)로 호출**해서 만든다. 별도의 키 발급 없이 기존 로그인을 그대로 쓰기 위한 선택이다. API 키 방식으로 바꾸려면 `summarize.py` 의 `call_model()` 하나만 교체하면 된다.

## 사용법

```bash
python3 yt-transcript.py "<유튜브 URL>"
```

### 옵션

| 옵션 | 설명 | 기본값 |
| --- | --- | --- |
| `--lang` | `orig`(원본 언어 자동 탐지) 또는 언어 코드(쉼표 구분, 앞에서부터 우선) | `orig` |
| `--format` | `md` / `json` / `both` | `md` |
| `--outdir` | 자막 출력 디렉터리 | `transcripts` |
| `--chunk` | N초 단위로 세그먼트를 병합해 문단화 (0이면 원본 유지) | `45` |
| `--no-auto` | 자동 생성(ASR) 자막 제외, 수동 자막만 사용 | off |
| `--from-json` | 이미 추출한 `.json` 을 재가공 (네트워크 요청 없음) | - |
| `--summary-dir` | 요약 출력 디렉터리 | `summaries` |
| `--model` | 요약에 쓸 모델 | `claude-opus-5` |
| `--no-summary` | 자막만 추출하고 요약은 건너뜀 | off |

### 예시

```bash
# 기본 — 원본 언어, 45초 문단, md 한 개
python3 yt-transcript.py "https://youtu.be/VIDEO_ID"

# 원본 대신 한국어 번역 트랙을 그대로 받고 싶을 때
python3 yt-transcript.py "https://youtu.be/VIDEO_ID" --lang ko

# 나중에 다시 가공할 수 있게 json 까지 함께 저장
python3 yt-transcript.py "https://youtu.be/VIDEO_ID" --format both

# 이미 뽑은 json 으로 문단 길이만 바꿔 재생성 (재요청 없음 → 429 회피)
python3 yt-transcript.py --from-json "transcripts/제목.json" --chunk 90
```

출력 파일명은 `<영상 제목>.<확장자>` 다. **같은 URL 을 다시 돌리면 기존 파일을 덮어쓴다** — 옵션을 바꿔가며 여러 번 실행해도 파일이 쌓이지 않고 항상 최신 결과 하나만 남는다. 덮어쓴 경우 출력이 `[완료]` 대신 `[덮어씀]` 으로 표시된다.

언어나 문단 길이가 다른 결과를 나란히 두고 비교하려면 `--outdir` 로 분리한다.

```bash
python3 yt-transcript.py "$URL" --outdir orig
python3 yt-transcript.py "$URL" --outdir ko --lang ko
```

## 번역은 요약 단계에서 한다

자동 자막만 있는 영상에는 보통 두 종류의 트랙이 존재한다.

- `en-orig` — **원본 음성을 그대로 인식한 트랙**
- `ko`, `ja`, … — 원본을 기계 번역한 트랙

기본값이 원본인 이유는, **유튜브 번역이 2초짜리 조각을 앞뒤 맥락 없이 옮기기 때문**이다. 같은 영상의 한국어 트랙에서 실제로 나온 오역이다.

| 원문 | 유튜브 번역 | 실제 의미 |
| --- | --- | --- |
| October low | 10월 최저 **기온** | 10월 **저점** |
| Wyckoff accumulation | **워프/화이트오프** 축적 | **와이코프** 축적 |
| $90k | **90km/h** | 9만 **달러** |
| Camirand (채널명) | 카**메론** | 카미랜드 |

일부 구간은 아예 번역되지 않고 영어로 남기도 한다. 번역본을 요약하면 이 오류가 그대로 굳고, 요약하는 쪽은 원문을 못 보므로 되돌릴 수 없다. 반대로 원본을 요약하면 LLM 이 전체 맥락과 도메인을 보고 한 번에 옮기므로 위 오역이 발생하지 않는다. 원문 대조가 필요할 때 근거가 남는다는 점도 있다.

부수적으로, 원본 트랙은 요청이 한 번이라 429 를 덜 만나고(번역 트랙은 별도 요청이다) 영어 입력이 한국어보다 토큰을 대체로 적게 먹어서 API 요약 비용도 낮다.

### 원본 트랙은 어떻게 찾나

`--lang orig` 은 다음 순서로 원본을 판별한다.

1. 자동 자막에 `*-orig` 키가 있으면 그것 (유튜브가 원본 음성 인식 트랙으로 표시한 것)
2. 메타데이터의 `language` (예: `en-US`) 와 일치하는 트랙, 수동 자막 우선
3. 수동 자막의 **첫 번째** 항목 — 유튜브가 주는 순서에서 원본이 앞선다. 알파벳순으로 정렬하면 안 된다 (`['en','de']` 를 정렬하면 원본이 아닌 `de` 가 앞선다)

요청한 언어가 없으면 사용 가능한 트랙 목록을 출력한다. `--lang ko,en` 처럼 여러 개를 주면 1순위가 없을 때 경고를 남기고 다음으로 넘어간다.

## 구현 메모

- **json3 포맷** 사용 — VTT보다 타임스탬프가 정밀하고 파싱이 단순하다.
- **롤링 중복 제거** — 자동 자막은 같은 문장이 여러 프레임에 반복 등장하는데, 직전 세그먼트와 텍스트가 같으면 `end` 만 늘리고 합친다.
- **구간 겹침 보정** — 각 세그먼트의 `end` 가 다음 `start` 를 넘지 않도록 잘라낸다.
- **429 백오프 재시도** — 유튜브가 자동 자막 요청에 `HTTP 429` 를 자주 돌려준다. 20초·40초·60초 간격으로 최대 4회 재시도한다.
- **언어 코드 접두사 매칭** — `ko` 요청 시 `ko-KR` 같은 지역 변형도 잡는다.

## 요약 (summaries/)

자막을 요약해 슬랙·카카오톡으로 흘려보내기 위한 부분. 핵심 규칙은 **요약을 '완성된 텍스트'가 아니라 구조(JSON)로 저장하고, 채널 형식은 보내기 직전에 입힌다**는 것이다.

```
URL → yt-transcript.py → transcripts/<제목>.md
                              ↓ (LLM 요약)
                         summaries/<제목>.json   ← 정본
                              ↓ render.py
        ┌─────────────┬─────────────┬─────────────┐
   <제목>.md      슬랙 블록      슬랙 스레드     카카오톡 텍스트
   (읽기용)      (핵심만)       (상세)        (1000자, 장식 없음)
```

슬랙 mrkdwn(`*굵게*`, `<URL|텍스트>`), 카카오톡 순수 텍스트, 마크다운은 문법이 전부 다르다. 요약을 텍스트로 저장하면 채널이 늘 때마다 다시 요약해야 하고 채널 간 내용이 어긋난다. 구조로 저장하면 렌더러만 추가하면 된다.

### 렌더링

```bash
python3 render.py "summaries/<제목>.json" --to kakao          # 순수 텍스트
python3 render.py "summaries/<제목>.json" --to slack          # Block Kit (핵심)
python3 render.py "summaries/<제목>.json" --to slack-thread   # Block Kit (상세)
python3 render.py "summaries/<제목>.json" --to md -o "summaries/<제목>.md"
```

표준출력으로 나가므로 그대로 파이프할 수 있다.

```bash
python3 render.py "summaries/<제목>.json" --to slack \
  | curl -sX POST -H 'Content-type: application/json' -d @- "$SLACK_WEBHOOK_URL"
```

### 스키마

| 필드 | 역할 | 길이 예산 |
| --- | --- | --- |
| `headline` | 한 줄 결론. 카톡 푸시 미리보기·슬랙 알림에 뜨는 부분 | ~100자 |
| `key_points[]` | 핵심 3~5개. **카카오톡은 여기까지만** 나간다 | 각 ~90자 |
| `sections[].points[]` | 상세. 슬랙 스레드와 `.md` 전용 | 제한 없음 |
| `entities.tickers` / `targets` | 라우팅·필터링용 구조화 값 | - |
| `disclaimer` | 고정 면책 문구 | - |

설계 의도:

- **깊이를 3단으로 고정한다.** 가변 깊이(1 → 1.1 → 1.1.1)는 웹에서는 읽히지만 채팅에서는 무너진다. 카카오톡에는 들여쓰기도 불릿도 굵게도 없다. 깊이가 고정이어야 "채널별로 어디까지 보낼지"가 스키마 수준에서 결정된다.
- **길이 예산을 요약 생성 시점에 건다.** 렌더 단계에서 자르면 문장이 중간에 끊긴다. 그래도 초과하면 `render.py` 가 항목 단위로 덜어내고 `…전체 5개 중 3개` 를 남긴다.
- **모든 주장에 `t`(초)를 붙인다.** 점프 링크 생성에 쓰이고, 동시에 요약의 각 문장이 원문 어디서 나왔는지 대조하는 수단이 된다. 자동 발송은 사람이 중간에 검수하지 않으므로 이 대조 경로가 사실상 유일한 안전장치다.
- **화자 귀속 문체를 쓴다.** 모든 주장은 `~라고 주장한다 / 본다 / 예상한다` 로 쓴다. 남에게 자동 발송되는 글에서 화자의 전망을 단정형으로 옮기면 요약자의 주장이 되어버린다.

### 템플릿 — `template.json`

출력 형식은 코드가 아니라 **`template.json` 한 파일**에 있다. 파이프라인의 세 단계가 모두 이 파일을 읽는다.

```
template.json
   ├─ rules, schema  → summarize.py 가 프롬프트를 만든다
   ├─ limits         → summarize.py 가 결과를 검사·보정한다
   └─ channels       → render.py 가 카카오톡·슬랙 한도로 쓴다
```

한 곳만 고치면 세 단계가 같이 따라온다. 이전에는 개수 규칙이 프롬프트 산문("3~5개")과 코드 상수 `(3, 5)` 에 따로 적혀 있어서, 한쪽만 바꾸면 조용히 어긋났다.

바꿔 끼울 수도 있다.

```bash
python3 yt-transcript.py "$URL" --template my-template.json
```

실제로 한도를 조인 템플릿으로 바꿔 돌린 결과다. 프롬프트·검증·렌더가 함께 따라온다.

| | `key_points` | `sections` | 카카오톡 |
| --- | --- | --- | --- |
| 기본 `template.json` | 5개 | 6개 | 595자 (한도 1000) |
| 변형 (2~3 / 1~2 / 400자) | 3개 | 2개 | 386자 (한도 400) |

어떤 템플릿으로 만든 결과인지는 요약 JSON 의 `source.template` 에 `youtube-summary-ko@1` 형태로 남는다.

### 템플릿이 지켜지는 방식

**프롬프트는 부탁이지 강제가 아니다.** `claude` CLI 에는 JSON 스키마로 생성 자체를 제약하는 수단이 없어서(Anthropic API 의 `output_config.format` 에 해당하는 옵션이 CLI 에 없다), 템플릿은 **생성 후 검사**로 강제한다.

`check()` 가 위반을 두 종류로 나눈다.

| 종류 | 처리 | 예 |
| --- | --- | --- |
| **치명적** — 구조가 깨져 렌더러가 터지는 것 | 무엇이 틀렸는지 모델에 되먹여 **재생성**(최대 3회) | `key_points` 가 배열이 아님, `text`/`points` 누락, `t` 를 초로 해석 불가 |
| **보정 가능** — 개수·길이·범위 | 잘라내거나 눌러서 맞추고 **무엇을 손댔는지 출력** | `key_points` 8개 → 5개, `t=999999` → 영상 길이로 클램프, `label` 없는 `figures` 제외 |

강제되는 값은 `template.json` 의 `limits` 에 있다 — `key_points` 3~5개, `sections` 3~6개, 섹션당 `points` 2~7개, `headline` 100자, 핵심 항목 90자.

위반 10종을 실제로 주입해 확인한다. `python3 tests/verify_template.py` 로 언제든 다시 돌릴 수 있다.

```
key_points 8개 (규칙 3~5개)      보정        md:ok kakao:ok slack:ok
key_points[0].text 누락          차단(재시도)  -
sections[0].points 누락          차단(재시도)  -
t=999999 (영상 길이 밖)           보정        md:ok kakao:ok slack:ok
key_points 가 배열이 아닌 문자열    차단(재시도)  -
```

**강제되지 않는 것도 있다.** 규칙 3(화자 귀속 문체), 규칙 6(전사 오류 교정), 번역 품질은 프로그램으로 검사할 수 없어 프롬프트에만 의존한다. 개수 미달(`sections` 1개 등)은 영상이 짧으면 정당할 수 있어 재생성 대신 경고만 남긴다.

### 요약 생성

`summaries/*.json` 은 자막을 읽은 Claude 가 위 템플릿에 맞춰 작성한다. 영상 메타데이터(제목·URL·길이)는 모델에게 맡기지 않고 자막 헤더에서 직접 읽어 채운다 — 틀릴 수 있는 값을 모델에 넘기지 않기 위해서다.

**입력은 원본 언어 자막, 출력은 한국어** 다. 번역과 요약을 한 번에 처리하는 셈인데, 이 단계의 LLM 은 영상 전체와 도메인을 보고 있으므로 유튜브의 조각 단위 번역보다 정확하다([앞 절](#번역은-요약-단계에서-한다) 참고).

## 할루시네이션 대책

LLM 요약의 두 약점(없는 사실, 호출마다 다른 결과)에 대한 대응이다.

### `grounding.py` — 원문 대조 검증 (LLM 없음)

요약의 각 주장에는 `t`(초)가 붙어 있다. 그 시점 앞뒤 구간의 자막만 꺼내, 주장 속 **숫자가 실제로 거기 나오는지** 순수 계산으로 대조한다. 지어낸 목표가·비율처럼 가장 해로운 할루시네이션이 숫자이기 때문이다.

```bash
python3 grounding.py "summaries/<제목>.json" [--window 90]
```

번역·전사 표기가 달라도 맞도록 정규화한다. 이 대응들이 실제로 필요했다.

| 요약 표기 | 원문 표기 | 정규화 |
| --- | --- | --- |
| `90K` | `the 90ks` (구어체 복수형) | 90000 |
| `5,140억 달러` | `514 billion dollar` | 514000000000 |
| `76.5K` | `76.5K의롱` (조사가 단위에 붙음) | 76500 |
| `10M` | `10밀리언` (영어 자릿수의 음차) | 10000000 |
| `0.618` | `618` (앞의 `0.` 을 빼고 말함) | 별칭으로 함께 인정 |
| `68~70K` | — | 앞 숫자에도 단위 적용 |

### `extract.py` — 추출 후 생성 (LLM 없음)

TextRank 로 중요 문단만 고른 뒤 그것만 모델에 넘긴다. 형태소 분석기 없이 **문자 3-gram** 유사도를 쓰므로 언어를 가리지 않고 외부 의존성도 없다.

```bash
python3 summarize.py "transcripts/<제목>.md" --extract 12
```

### 결정성

`temperature=0` 은 답이 아니다. 완전 재현성을 보장한 적이 없고, **Opus 5 에서는 파라미터 자체가 제거돼 보내면 400** 이다. 같은 입력에 같은 출력이 필요하면 자막 해시로 캐싱해 호출 자체를 건너뛰는 편이 확실하다.

## 한계

자막 트랙 자체가 없는 영상은 이 방식으로 추출할 수 없다. 그 경우 음성을 내려받아 Whisper 등으로 STT를 돌려야 한다.
